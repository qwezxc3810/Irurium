# 생성 엔진 검증실 (단계 A)

이루리움의 핵심 경험인 **"기록과 감정에 따라 나만의 어항이 자란다"**를 실제 엔진·렌더러로 확인하는 도구예요.
근거 문서: v0.3.1 수정 노트 6장(가설 H1~H11, 검증 사례 A~F), v0.3.2 기술 보완서.

- 실행: `npm run dev` 후 `http://localhost:5173/lab.html` (어항 시뮬레이터 화면의 "생성 엔진 검증실 열기" 링크로도 이동)
- 보고서: `npm run lab:report` → [`docs/validation/REPORT.md`](validation/REPORT.md)
- 테스트: `npm test` (검증실 테스트는 `src/lab/__tests__/lab.test.ts`)

## 원칙

| 원칙 | 어떻게 지키나 |
|---|---|
| 엔진·렌더러 재사용 | 샘플 기록을 실제 앱과 같은 `TankSession`에 넣는다(확정 순서·24시간 확정·완독 확인까지 동일). 그림은 같은 `AquariumRenderer`로 그린다. 엔진을 흉내 낸 별도 계산이 없다. |
| 실제 앱과 분리 | 검증 코드는 `src/lab/`, 화면은 별도 진입점 `lab.html`. 앱에 추가한 것은 "검증실로 보내기" 버튼과 링크뿐. 렌더러에는 정지 그림 모드(`init(null, { still })`, `renderStill()`)만 더했고 기존 동작은 그대로. |
| 엔진을 바꾸지 않음 | 엔진 수치·규칙·`ENGINE_VERSION`(0.1.0) 그대로. main(b809973)과 같은 어린왕자 재생 해시(`897f99bd:a2f000ff`)가 나오는지 테스트로 고정. |
| 샘플과 실제 기록 구분 | 샘플 어항 id·기록 id는 모두 `sample:` 접두사, 실행기는 접두사가 없으면 거부. 화면 곳곳에 출처 배지(샘플 / 실제 기록·읽기 전용 / 실제 기록 기반 가상 실험). 실제 기록에 `sample:` 어항을 넣으면 거부. |
| 기존 스냅샷을 바꾸지 않음 | 샘플은 매번 새 세션. 실제 기록은 가져오자마자 깊게 얼리고(`Object.freeze`), 저장된 스냅샷을 그대로 보여 준다. 무결성 확인은 다시 계산한 해시를 비교만 한다. 시드를 바꿔 보는 실험은 기록을 복사해 `derived:` 어항으로 따로 돌리고, 전후 원본 지문이 같은지 화면에 표시한다. |

## 지표 정의 [검증용 정의 — 엔진 결과에 영향 없음]

- **성장 단계**: 상한 합계 32개(물고기 12·수초 10·수석 6·상징 4) 대비 채움. 1 빈 어항 · 2 새싹(<15%) · 3 자라는 중(<40%) · 4 풍성(<75%) · 5 가득
- **물빛 색감**: 세미 리얼 배경 가운데 평균색 `#043877`에 렌더러와 같은 감정 조명 색 보정(`src/render/lighting.ts`: 색온도·채도·밝기 행렬 + 왼쪽 위 가산 빛)을 적용한 화면 평균색. 이름은 조명 방향과 가장 가까운 마음 칩
- **어항 차이(물빛+구성)**: (조명 벡터 차이 ÷ 2 + 요소 구성 분포의 총변동거리) ÷ 2, 0~1. 배치(위치)는 뺀다 — 시드가 만드는 개성과 감정이 만드는 차이를 나눠 보려고
- **배치 차이**: (요소, 50px 칸) 집합의 자카드 거리
- **감정 구별(수치 기준)**: 감정만 다른 어항 쌍의 최소 차이 > 시드만 다른 어항 쌍의 최대 차이. 엔진 상태로 계산한 상대 지표이고 지금 샘플·지금 가중치에서만 성립한다. **시각적으로 한눈에 구별된다는 뜻이 아니다** — 그건 짝짓기 테스트(사람 평가)로 따로 확인한다.

## 판정 규칙

- **통과(자동 기준)**: 시뮬레이터로 잴 수 있는 기준을 넘었다. 지인 테스트로 갈 수 있다는 뜻이지 확정이 아니다.
- **조정 필요**: 자동 기준을 못 넘었거나, 문서의 초깃값과 구현이 다르다.
- **보류(사람 평가 필요)**: 기준이 사람 평가·실기기 측정이라 샘플로는 판단할 수 없다. 자동으로 잰 부분이 좋아도 통과로 올리지 않는다(H1·H2·H3·H8·H11). 테스트가 이것을 강제한다.

엔진 수치를 바꿀 때는 v0.3.1 6.3 절차대로 **한 번에 하나만** 바꾸고 `ENGINE_VERSION`을 올린다. 그 전 기록의 스냅샷은 바꾸지 않는다.

## 첫 측정에서 발견한 것 (엔진 0.1.0, 샘플 기준)

자세한 수치는 [REPORT.md](validation/REPORT.md). 이번 PR에서는 **측정만 하고 엔진 수치는 바꾸지 않았어요.**

1. **H5 조정 필요** — 100일 이후 특별 변화 공백. 꾸준형 200일에서 131~160일에 특별 변화가 0회. 누적 마일스톤이 100 → 150 → 200회로 벌어지기 때문.
2. **H9 조정 필요** — 연속 성장에서 같은 종류 33%(기준 20% 미만). 새로 놓는 요소는 5%로 괜찮지만, 어항이 찬 뒤 "기존 요소 키우기"에는 반복 감점이 없음. 또 카탈로그의 같은 요소 최대 개수(송사리 5 등)가 H9 초깃값 2개와 다름(요소 종류가 적어서).
3. **H4 해석 필요** — 사례 C는 8회로 통과지만, 14일을 매일 기록하면 11회(특별 변화 포함 매일 주요 변화).
4. **감정 구별: 수치 기준 통과, 시각적 구별은 미검증** — 감정만 다른 어항끼리 최소 차이 0.288 > 시드만 다른 어항끼리 최대 0.131(따뜻함–유쾌함이 가장 비슷한 쌍). 임시 SVG·물고기 3종이라 화면상 차이는 더 작을 수 있어 짝짓기 테스트 대기.
5. **비주얼** — 따뜻한 감정 조명(호박색)을 남색 물 위에 덧칠하면 물빛이 탁한 회갈색으로 보였어요 → 2026-11-14 색 보정 방식으로 바꿨어요(아래 "감정 조명" 절).
6. **감정 없는 어항(E)** — C와 같은 개수(9개)로 자라지만 물고기가 1마리라 비어 보일 수 있음. 사람 평가 필요.

## 실제 기록 표시의 한계

- **마무리(wrapped)** 는 스냅샷을 추가하지 않고 머리를 고정하는 정책이라 마무리한 날짜가 데이터에 없어요. 그래서 마지막 기록 날짜 프레임에만 '마무리'로 표시하고, 지난 날짜로 소급하거나 그 뒤 날짜를 만들어 내지 않아요. 화면에 이 한계를 함께 안내해요.
- **완성(completed)** 은 완성 스냅샷이 생긴 날부터 '완성'으로 표시해요.

## 화면 표시 규칙과 가림 지표 (이슈 #6)

오래 자란 어항에서 수초가 물고기를 가리던 문제를 **엔진이 아니라 화면 표시 규칙**(`src/render/display.ts`)으로 줄였어요. 스냅샷과 `ENGINE_VERSION`은 그대로이고, 이미 자란 어항에도 바로 적용돼요.

| 규칙 | 값 |
|---|---|
| 1배를 넘는 성장은 일부만 커 보이게 | 수초 50%, 물고기 60% (수초 1.5배 → 1.25배로 보임) |
| 앞쪽(front) 수초는 전경용으로 낮게 | 원래 높이의 60% |
| 물고기가 앞쪽 수초 뒤를 지나면 | 수초 투명도 0.55 |
| 물고기 헤엄 높이 | 엔진 레인(170·290·400)에서 ±3칸(22px) 안에서, 먼저 태어난 물고기부터 세로로 가장 덜 겹치는 높이(새 물고기가 생겨도 기존 물고기는 그대로) |

검증실 "장기" 탭 맨 아래와 보고서 8장에 이전·지금 규칙의 가림 지표를 나란히 보여 줘요(기준은 검증용 가설: 실제 가림 10% 미만, 수초 꼭대기 y 150 아래). **지표는 샘플 시작 위치 기반 근사값이에요.** 0%는 "샘플 어항의 시작 위치에서 사각형끼리 겹치지 않는다"는 뜻이에요. 헤엄 중 위치, 수초 흔들림, 투명한 픽셀 모양은 반영하지 않아서 실제 화면에서 순간적인 가림은 생길 수 있어요. 움직이는 화면(검증실 갤러리에서 그림을 눌러 열기)으로 함께 확인해 주세요. 물고기 8마리 이상 큰 어항의 헤엄 띠 겹침은 화면 규칙만으로는 남아서, 물고기 수·크기 상한(엔진, H8) 실험이 후속 과제예요.
