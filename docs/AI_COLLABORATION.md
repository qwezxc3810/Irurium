# AI 협업 방식

이 저장소는 기획자, Claude, ChatGPT가 함께 쓰는 작업 공간입니다. 두 AI가 서로 직접 대화하지는 않고, **GitHub PR을 사이에 두고** 일합니다.

## 역할

| 누구 | 하는 일 |
| --- | --- |
| 기획자 | 방향 결정, 리뷰 의견 중 반영할 것 고르기, 머지 결정 |
| Claude | 기능 브랜치에서 개발, PR 작성, 리뷰 의견 반영 커밋, 테스트 |
| ChatGPT | PR 코드 리뷰, 그래픽 리소스 제작, 기획 관점 검토 |

## 흐름

1. 기획자가 Claude에게 작업을 요청합니다.
2. Claude가 `feat/…` 또는 `fix/…` 브랜치를 만들어 개발하고 PR을 엽니다. PR 설명에는 항상 세 가지가 있습니다.
   - 구현한 내용
   - 테스트 방법(명령어와 화면에서 눌러 볼 것)
   - 아직 구현하지 않은 부분
3. 기획자가 ChatGPT에게 PR 링크를 주고 리뷰를 요청합니다. ChatGPT가 PR에 코멘트를 남길 수 없으면, 리뷰 내용을 기획자가 PR 코멘트로 붙여 넣습니다.
4. 기획자가 Claude에게 "PR #번호 리뷰 반영해 줘"라고 요청합니다. Claude는 PR 코멘트를 읽고 같은 브랜치에 수정 커밋을 올린 뒤, 반영한 것과 반영하지 않은 것(이유 포함)을 PR에 코멘트로 남깁니다.
5. 기획자가 머지합니다. `main`에 직접 커밋하지 않습니다.

## 리뷰어(ChatGPT)에게 부탁하는 것

리뷰할 때 아래 순서로 보면 효율적입니다.

1. `README.md`의 설계 원칙과 불변 규칙
2. `src/engine/` — 엔진이 문서의 규칙대로 동작하는지(특히 `compute.ts`, `session.ts`)
3. `src/engine/__tests__/` — 테스트가 규칙을 제대로 검증하는지
4. `src/render/` — 그리기 코드가 상태를 바꾸지 않는지, 성능 문제는 없는지
5. `docs/ASSET_SPEC.md` — 그래픽 규격이 실제 제작 가능한지

리뷰 코멘트는 이렇게 써 주면 반영이 빠릅니다.

```
[필수|권장|질문] 파일:줄 — 문제 한 줄
이유: …
제안: …
```

## 그래픽 리소스 전달

ChatGPT로 만든 이미지는 기획자가 Claude와의 대화에 올리거나 PR에 첨부합니다. Claude가 배경 제거·크기 조정 후 `public/assets/`에 넣고 매니페스트를 고쳐 커밋합니다. 규격은 `docs/ASSET_SPEC.md`.

## 브랜치 이름

- `feat/<기능>` 새 기능 (예: `feat/aquarium-simulator`)
- `fix/<문제>` 버그 수정
- `assets/<내용>` 그래픽 리소스 교체
- `docs/<내용>` 문서만 수정
