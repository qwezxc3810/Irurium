## 고친 점 (최소 변경, 성장 규칙은 그대로)
1. **깊은 무결성 검사의 오탐**
   - 원인: `checkInvariants({deep:true})`가 0.1.0 스냅샷까지 0.2.0으로 다시 계산해서, 이 고정 파일에서 "다시 계산하면 결과가 다름(I2)" 오류가 31개 났어요. 데이터는 멀쩡했어요.
   - 수정: 다시 계산(I2)은 **지금 엔진 버전 스냅샷만** 해요. 그 전 버전 스냅샷은 다시 계산하지도 덮어쓰지도 않아요.
2. **불러오기 없음**
   - 원인: `toJSON()`만 있고 불러오는 길이 없었어요.
   - 수정: `TankSession.fromJSON()`을 추가했어요. 저장된 스냅샷을 그대로 쓰고, 구조·해시가 맞지 않으면 불러오지 않아요(`session_invalid`).
   - **아직 앱 화면은 어항을 저장하지 않아요.** 저장 기능을 넣을 때 이 길을 써요.
3. **버전과 관계없는 검사 추가**
   - **I5 기록 체인 구조:** 머리 → 시작 한 줄, 갈래·고아·순환 없음, 순번, 기록 순번·id·clientId.
   - **I6 입력 해시 체인:** 기준의 입력 해시 + 입력 + 엔진 버전. 0.1.0과 0.2.0이 같은 식을 써서 다시 계산 없이 확인할 수 있어요.
   - 검증실 "실제 기록" 검사에도 I6을 넣고, 기준 체인 이름을 I5로 맞췄어요.

`ENGINE_VERSION`(0.2.0)·골든 해시·성장 규칙은 바뀌지 않았어요.

## 7. 섞인 기록 무결성 검사: 확인할 수 있는 것 / 없는 것
| | 0.1.0 스냅샷 | 0.2.0 스냅샷 |
|---|---|---|

| 기준·순번·순환·갈래·중복 (I5 구조) | ✅ | ✅ |
| 입력·기준·엔진 버전 표시가 바뀌었는지 (I6 입력 해시) | ✅ | ✅ |
| 저장된 입력으로 다시 계산하면 같은지 (I2) | ❌ 다시 계산 안 함 | ✅ |
| 그때 규칙으로 **맞게 계산됐는지** | ❌ 0.1.0 엔진이 없어서 | ✅ (I2) |
| 상태와 내용 해시를 **함께** 고쳐 쓴 경우 | ❌ 못 잡음 (단, 바로 위에 0.2.0 스냅샷이 이어져 있으면 그 스냅샷의 I2가 어긋나서 잡힘) | ✅ (I2) |

- 못 잡는 경우는 테스트로 고정했어요(`7. … 확인할 수 없음`). 바뀌면 이 표도 고쳐야 해요.
- 이 검사들은 실수·손상을 찾는 용도예요. 일부러 모든 해시를 다시 계산해 고쳐 쓰는 위조는 막지 못해요(서명이 없음).
- 이 한계를 없애려면 버전별 엔진을 같이 보관해 그때 규칙으로 다시 계산해야 해요(이슈 #12 후속).
