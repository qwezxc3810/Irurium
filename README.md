# 이루리움(가제) · Irurium

> 나의 모든 성장이 어항이 되고, 그 어항들이 모여 나만의 수족관이 된다.

자기계발 기록(독서부터 시작)이 쌓이면 그 기록과 감정에 따라 어항이 자동으로 자라는 앱입니다.
이 저장소의 첫 단계는 **실제로 움직이는 어항 하나**를 만드는 시뮬레이터입니다. 로그인·서버·커뮤니티·수익 모델은 아직 없습니다.

이 저장소는 ChatGPT와 Claude가 함께 보는 공통 작업 공간입니다. Claude가 코드를 쓰고, ChatGPT가 코드를 리뷰하거나 그래픽 리소스를 만들고, 기획자가 PR에서 방향을 정합니다(아래 [AI 협업 방식](#ai-협업-방식)).

## 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev        # 개발 서버 → http://localhost:5173
npm test           # 엔진 단위 테스트(Vitest)
npm run build      # 타입 검사 + 배포용 빌드(dist/)
npm run preview    # 빌드 결과 미리보기
npm run lab:report # 생성 엔진 검증 보고서 → docs/validation/REPORT.md
```

- 어항 시뮬레이터: `http://localhost:5173/`
- 생성 엔진 검증실: `http://localhost:5173/lab.html` — 사례 A~F, 비교 실험, 14~200일 장기, 가설 H1~H11 판정, 짝짓기 테스트. 자세한 내용은 [docs/VALIDATION.md](docs/VALIDATION.md)
  - 검증실의 감정 구별은 **수치 기준**이에요(시각적 체감은 짝짓기 테스트 대기). 통과(자동 기준)도 확정이 아니라 지인 테스트로 넘어갈 수 있다는 뜻이에요.

### 설계 원칙

1. **엔진과 그림의 분리.** 엔진은 요소 id(`fish.medaka`)만 다루고, 어떤 그림 파일을 쓸지는 `public/assets/manifest.json`이 정합니다. 그래픽을 바꿀 때 코드를 고치지 않습니다.
2. **재현성.** 엔진은 순수 함수입니다. 현재 시각과 `Math.random`을 쓰지 않고, 어항 시드와 기록 순번으로 만든 난수만 씁니다. 같은 기록이면 언제나 같은 어항이 나옵니다.
3. **확정된 과거는 바꾸지 않음.** 스냅샷은 확정되면 다시 계산하지 않습니다. 확정 후 기록을 고치면 기록과 수정 이력만 바뀝니다.
4. **렌더러는 상태를 바꾸지 않음.** 렌더러의 무작위(기포 위치 등)는 화면 연출일 뿐 저장되는 상태에 영향을 주지 않습니다.

### 불변 규칙 (v0.3.2 보완서 1.2)

`session.checkInvariants({ deep })`가 아래 규칙을 검사합니다. 화면은 매번 가벼운 검사(`deep: false`), 테스트와 "재현성 확인" 버튼은 깊은 검사(`deep: true`)를 씁니다.

| 규칙 | 내용 | 검사 방법 |
| --- | --- | --- |
| I1 | 미확정 스냅샷은 어항당 최대 1개, 삭제되지 않은 가장 마지막 기록의 것 | 미확정 개수, 소속 기록, 머리 위치 비교 |
| I2 | 스냅샷 n = computeSnapshot(직전 확정 스냅샷, 기록 n) | 기준이 확정본인지 + (깊은 검사) 스냅샷에 저장된 입력·설정으로 다시 계산해 결과 해시 비교 |
| I3 | 확정 스냅샷은 바뀌지 않음 | 만들 때 저장한 contentHash와 현재 내용 해시 비교 |
| I4 | 기록 날짜는 어항 안에서 줄어들지 않음 | 기록 순서대로 날짜 비교 |

스냅샷은 계산에 쓴 입력(`input`)과 설정(`cfg`)을 함께 저장합니다. 그래서 확정 후 기록을 고치거나 총 쪽수를 바꿔도 과거 스냅샷은 당시 값으로 재현됩니다.

### 삭제한 기록과 이끼

- 확정 후 지운 기록(`hidden`)은 어항이 그대로이고 활동 사실도 남아서 이끼 기준일에 포함합니다. 지웠다고 이끼가 갑자기 생기지 않게 하려는 것입니다.
- 미확정 상태에서 지운 기록(`discarded`)은 실수 입력으로 보고 스냅샷과 함께 버리며 이끼 기준일에서도 뺍니다.
- 폐기한 기록은 어항의 기록 흐름에서도 빠집니다. 새 기록의 날짜 보정(I4)도 폐기한 기록의 날짜를 기준으로 삼지 않습니다. 숨긴 기록은 스냅샷이 남아 있으므로 날짜 보정 기준에 그대로 포함됩니다.

## 그래픽 리소스 교체

1. [docs/ASSET_SPEC.md](docs/ASSET_SPEC.md)의 규격대로 이미지를 만듭니다. 물고기는 머리가 오른쪽인 옆모습 한 장(투명 PNG)이면 됩니다.
2. `public/assets/` 아래 같은 경로에 같은 이름으로 덮어쓰거나, 새 파일을 넣고 `manifest.json`의 경로를 바꿉니다.
3. 크기는 `displayWidth` / `displayHeight`로, 헤엄·흔들림 정도는 `swim` / `sway`로 조정합니다.
4. 파일을 못 불러오면 화면에 대체 그림과 경고가 나오고 앱은 계속 동작합니다.

## AI 협업 방식

[docs/AI_COLLABORATION.md](docs/AI_COLLABORATION.md)를 참고하세요. 요약하면 다음과 같습니다.

- Claude: 기능 브랜치에서 개발 → PR 작성(구현 내용, 테스트 방법, 미구현 목록)
- ChatGPT: PR의 코드를 읽고 리뷰 의견을 남기거나 기획자에게 전달, 그래픽 리소스 제작
- 기획자: 리뷰 의견 중 반영할 것을 고르고 Claude에게 요청 → Claude가 같은 브랜치에 수정 커밋
- `main`에는 직접 커밋하지 않습니다.
